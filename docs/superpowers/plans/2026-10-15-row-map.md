# Row Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. No sub-agents: the owner's standing rule.

**Goal:** For every transaction a PDF statement's reading produces, the reader records which
printed lines (page and y position, no text) went into it. Blanked copies carry that row map. The
blanked-copy check compares it between the real and the copy reading, and the admin panel points
out unusual rows. Every statement must read byte-for-byte as before.

**Architecture:**
- `PdfTableLocator` keeps an identity-keyed side table from each row `Map` to the physical lines
  it was built from. It fills the table where a row is bucketed from a physical line, and unions
  it wherever one row merges into another.
- Each `LocatedSection` it returns gains `rowLines`, a list aligned with `rows`. Row maps
  themselves are never touched, so nothing that reads a row's cells can see the record.
- `PdfPreviewGenerator` gains an overload of `generateSectionsFromAcquired` that takes a sink.
  The sink receives each section's row lines, numbered as rows are shown on screen, using the
  `displayedPositionOfLocatedRow` mapping that already exists. Every import path calls the old
  overload, so nothing is retained there.
- `BlankedCopyService`:
  - collects the real reading's row map and appends it to the copy as `#` comment lines;
  - compares it with the copy reading's map under a new difference field `ROW_LINES`;
  - computes the unusual-row flags for the response.

**Tech Stack:** Java 25, JUnit 5, AssertJ; the admin portal in React + TypeScript with Vitest;
Python 3 for `scripts/corpus-run.py`. Node 22 (`npx node@22`).

**Spec:** `docs/superpowers/specs/2026-10-15-row-map-design.md`. Its third unusual-row rule was
corrected while planning: a gap more than 3× the page's median line gap, not "below every other
row".

## Global Constraints

**What the record holds, and where it goes**
- The record holds page indexes and y positions only. A y position is rounded to hundredths, as
  `TraceFormat` writes it, so the real and the copy readings compare equal.
- Row `Map`s are never given a new key or a new marker character. `LineGeometry`'s marks are a
  precedent for cell marks, and are not to be extended for this.
- The record never reaches a staged row, a session's JSON, a stored finding, a `DocumentContext`
  fact, an audit entry or a log line. Only the sink overload exposes it, and only
  `BlankedCopyService` calls that overload.

**Reading must not change**
- `scripts/corpus-run.py` output over the owner's local statements is byte-identical between
  `origin/main` and the branch.
- The private trace tests pass with the same count (`-Pprivate-traces`, see
  `docs/engineering/private-statement-traces.md`).
- A parser PR is not merge-ready until the private trace tests pass for it: the repo rule since
  #2193.

**Privacy**
- Never print a real statement's content. Corpus measurements report counts only.
- The row map block in a copy must pass `TraceValidator`'s privacy checks. If `copyLeaks` objects
  to the block's digits, exclude exactly those `#` lines from that check, with a test. Never
  loosen the check for run lines.

**Repository rules**
- Commit messages carry no `Co-Authored-By` or any AI-attribution trailer.
- Work only in your own worktree from `origin/main`. Never write in `/Users/sid/Downloads/finora`.
- `./mvnw test` skips ITs; the full run is `./mvnw verify`. Never commit while `verify` runs.
- Tests plant synthetic values only. Mark customer-shaped values `// synthetic-ok`.

## Review Focus

1. **A wrapped narration whose second line is a continuation row merged into the row above.**
   Expected: the row records both lines. Test in Task 2 (`aContinuationLineJoinsTheRowAbove`).
2. **A leading narration line printed above its date line** (the `pendingLeading` path). Expected:
   the row records the leading line and the date line, in page order. Test in Task 2
   (`aLeadingNarrationLineIsRecorded`).
3. **A row whose lines straddle a page break.** Expected: both pages are recorded, and the panel
   flags the row as two-page. Tests in Task 2 (`aRowAcrossAPageBreakRecordsBothPages`) and Task 5.
4. **A located row that never stages** (a balance line, or a row that failed to normalise).
   Expected: it's left out of the map, and later rows keep their displayed numbers. Test in Task 3
   (`aRowThatDoesNotStageIsLeftOut`).
5. **A newest-first statement.** Expected: map row numbers are the displayed positions, not
   document order. Test in Task 3 (`rowNumbersAreDisplayedPositions`).

```java
package com.finora.imports.pdf;

import java.util.*;

/** The printed lines one transaction row was read from: page and y only, never text (see
 *  docs/superpowers/specs/2026-10-15-row-map-design.md). y is in hundredths of a point, the
 *  precision a trace writes, so a reading of the real runs and of a blanked copy compare equal. */
public record RowLines(List<Line> lines) {

    public static final RowLines NONE = new RowLines(List.of());

    public record Line(int page, int yHundredths) implements Comparable<Line> {
        @Override public int compareTo(Line o) {
            return page != o.page ? Integer.compare(page, o.page) : Integer.compare(yHundredths, o.yHundredths);
        }
    }

    public RowLines { lines = List.copyOf(lines); }

    /** One physical row is one line, at its topmost run. */
    public static RowLines of(List<PositionedText> physicalRow) {
        if (physicalRow.isEmpty()) return NONE;
        PositionedText top = physicalRow.stream().min(Comparator.comparingDouble(PositionedText::y)).orElseThrow();
        return new RowLines(List.of(new Line(top.pageIndex(), Math.round(top.y() * 100))));
    }

    public RowLines union(RowLines other) {
        TreeSet<Line> all = new TreeSet<>(lines);
        all.addAll(other.lines);
        return new RowLines(new ArrayList<>(all));
    }

    public boolean isEmpty() { return lines.isEmpty(); }
}
```

`RowProvenance` wraps an `IdentityHashMap<Map<String, String>, RowLines>`. `record` unions into
whatever is there already, `merge` unions the source's lines into the target's, and `transfer`
copies the record to the new map.

Check how `TraceFormat` writes y (`%.2f` or similar). If it truncates rather than rounds, match
it exactly and change the first test's expectation to what it writes.

  row's lines on that page, in y order. With fewer than 3 such gaps on the page, `FAR_LINE` is not
  judged.
